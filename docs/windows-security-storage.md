# Windows 계정 파일 저장 및 복구

## 요청과 결정

WindowsSecurity 코드 리뷰에서 기존 파일 직접 덮어쓰기로 인한 계정 데이터 손실과 복호화 실패 후 재로그인 차단을 확인했다. 두 문제를 함께 수정하고 PR로 제출한다.

- 암호문을 같은 디렉터리의 고유한 임시 파일에 기록하고 디스크로 flush한 뒤 원본을 교체한다. 최초 저장은 파일 이동을 사용하며, 실패한 교체는 기존 파일을 보존하고 임시 파일을 정리한다.
- 복호화 또는 JSON 파싱에 실패한 파일은 즉시 삭제하고 빈 저장소로 처리한다. 이후 계정 관리자가 새 계정을 저장할 수 있다.
- 읽기, 손상 파일 삭제, 저장의 I/O 오류는 호출자에게 전달한다. 삭제에 실패한 파일을 빈 저장소로 처리하지 않는다.
- 기존 생성자, 인터페이스와 DPAPI CurrentUser 암호문 형식은 유지한다. 동시 프로세스 사이의 계정 목록 병합은 이 변경의 범위에 포함하지 않는다.

## 후속 요청과 최종 반영

처음에는 손상 파일을 `.corrupt.<고유 ID>` 이름으로 보관하도록 구현했다. 사용자가 보관 대신 즉시 삭제를 요청해 `File.Delete`로 변경했다. 기존에 생성된 보관 파일을 일괄 삭제하는 동작은 추가하지 않았다.

사용자 요청에 따라 추가했던 `.github/workflows/windows-security-tests.yml`, `XboxAuthNet.Game.WindowsSecurity.Test` 프로젝트와 솔루션 등록을 제거했다. 이 단계에서는 저장·복구 구현과 이 문서만 변경하고 기존 예제와 테스트는 유지했다. 앞으로 명시적인 지시 없이 워크플로를 추가·수정하지 않는다.

## 검증 기록

최초 커밋 `069e3ca`에서 로컬 Linux Release 빌드와 파일 미존재 테스트 1개가 통과했고 해당 커밋의 Windows CI 실행도 성공했다. 이는 손상 파일을 보관하던 구현에 대한 결과이며 즉시 삭제 변경에 대한 Windows 실행 검증은 아니다. 이후 사용자의 요청으로 추가 테스트와 워크플로를 제거했다.

즉시 삭제 변경 후 WindowsSecurity 프로젝트의 Linux Release 빌드가 경고·오류 없이 통과했다. Windows DPAPI 실행 테스트는 수행하지 않았다.

## 평문 계정 파일 마이그레이션

사용자는 기존 `cml_accounts.json`을 Windows 암호화 저장소로 옮기는 헬퍼를 요청했다. 최초 요청의 `cml_sesisons.json`은 오타이며 구버전 단일 세션 형식 변환은 필요하지 않다고 확인했다.

`ProtectedJsonFileStorage.TryMigrateFromJson(jsonFilePath)`을 추가했다. 대상 경로는 생성자에 지정하며, 기존 계정별 JSON 객체와 알 수 없는 필드를 그대로 암호화한다. 같은 원본·대상 경로는 거부하고, 원본이 없거나 대상 파일이 이미 존재하면 false를 반환한다. 대상 파일의 정상 여부를 검사하거나 기존 파일을 삭제·덮어쓰지 않는다.

JSON이 객체가 아니거나 파싱·암호화·파일 작업이 실패하면 오류를 전달하고 원본을 유지한다. 암호화 임시 파일의 기록과 flush가 끝난 뒤 덮어쓰지 않는 이동으로 대상을 생성하고, 그 후에만 평문 원본을 삭제한다. 검사 이후 다른 프로세스가 대상을 생성하면 이동은 실패하고 원본은 유지된다. 원본 삭제에 실패하면 암호화 대상은 남고 예외를 전달한다. 이 경우 다음 호출은 대상 존재로 건너뛰므로 평문 파일 삭제 문제를 별도로 해결해야 한다.

기존 WindowsSecurityTest 예제에서 기본 폴더의 `cml_accounts.json`을 `cml_accounts_ws.bin`으로 전환한 뒤 같은 저장소로 계정 관리자를 구성한다. 마이그레이션은 계정 파일을 다른 프로세스가 쓰지 않는 앱 시작 단계에서 호출한다. 새로운 테스트 프로젝트나 워크플로는 추가하지 않는다.

```csharp
var storage = new ProtectedJsonFileStorage(encryptedPath);
storage.TryMigrateFromJson(accountsJsonPath);
```

마이그레이션 추가 후 Release 빌드가 통과했다. 저장소 밖의 임시 실행 프로그램으로 원본·부모 디렉터리 미존재, 기존 대상과 원본 보존, 동일 경로 거부, 잘못된 JSON·null·배열 거부, Linux의 DPAPI 미지원 시 원본 보존과 임시 파일 미생성을 포함한 11개 조건을 확인했다. Windows에서 성공하는 암호화 전환은 실행 검증하지 못했다.
