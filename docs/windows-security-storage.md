# Windows 계정 파일 저장 및 복구

## 요청과 결정

WindowsSecurity 코드 리뷰에서 기존 파일 직접 덮어쓰기로 인한 계정 데이터 손실과 복호화 실패 후 재로그인 차단을 확인했다. 두 문제를 함께 수정하고 PR로 제출한다.

- 암호문을 같은 디렉터리의 고유한 임시 파일에 기록하고 디스크로 flush한 뒤 원본을 교체한다. 최초 저장은 파일 이동을 사용하며, 실패한 교체는 기존 파일을 보존하고 임시 파일을 정리한다.
- 복호화 또는 JSON 파싱에 실패한 파일은 `.corrupt.<고유 ID>` 이름으로 이동해 보존하고 빈 저장소로 처리한다. 이후 계정 관리자가 새 계정을 저장할 수 있다.
- 읽기, 보관 파일 이동, 저장의 I/O 오류는 호출자에게 전달한다. 보관에 실패하면 원본을 덮어쓰지 않는다.
- 기존 생성자, 인터페이스와 DPAPI CurrentUser 암호문 형식은 유지한다. 동시 프로세스 사이의 계정 목록 병합은 이 변경의 범위에 포함하지 않는다.

## 검증

별도 테스트 프로젝트와 Windows CI에서 정상 생성·교체, 교체 실패 시 원본 보존과 임시 파일 정리, 잘린 암호문·빈 파일·잘못된 JSON의 보존과 복구, I/O 오류 전파, 계정 관리자 저장 재개를 검증한다. Linux에서는 DPAPI를 실행할 수 없으므로 Windows 전용 테스트를 건너뛴다.

로컬 Linux에서 Release 빌드와 파일 미존재 테스트 1개가 통과했다. DPAPI가 필요한 7개 테스트는 운영체제 조건으로 건너뛰었으며 PR의 Windows CI에서 실행한다.
